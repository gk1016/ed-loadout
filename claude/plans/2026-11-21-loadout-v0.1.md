# LOADOUT v0.1 — Windows binary, highest-version fxcfg, default Options dir

## Goal
Make v0 runnable on devmachine02 and the laptop: a Windows `.exe` from the WSL runner by cross-compile, the multiple-`fxcfg` refusal replaced by the rule Elite itself follows, and the Options dir found without typing it.

## Non-goals
GUI. ED-UP `edvr*.ini` (still no real fixture). HID enumeration. Code signing. Any change to the fixture corpus.

## Context
v0 merged as `ed7c4a2` (PR #2, report `claude/reports/2026-11-21-loadout-v0.md`). Lane issue #1. `ISSUES.md:15` OBS-002 is the fxcfg refusal at `src/apply.rs:152-160` ("expected exactly one"); `check-binds` has a parallel "newest file" rule for binds in `src/binds.rs`. The WSL runner already has `x86_64-w64-mingw32-gcc` at `/usr/bin` and the `x86_64-pc-windows-gnu` rustup target installed (checked 2026-11-21 18:30Z on the EVO-X2); `build.yml:27-33` now also runs `cargo check --target x86_64-pc-windows-gnu` (pushed with this plan) so the `cfg(windows)` paths compile on every PR. `.github/workflows/release.yml` (pushed with this plan) builds the Windows and Linux binaries on `workflow_dispatch` / `v*` tag and attaches them to a GitHub Release; Cowork cuts the tag after merge. `Cargo.toml:3` is `0.1.0`.

## Acceptance criteria
1. `cargo build --release --target x86_64-pc-windows-gnu` succeeds on the WSL runner and produces `target/x86_64-pc-windows-gnu/release/ed-loadout.exe`; `file` on it reports `PE32+ executable (console) x86-64`. Any `cfg(windows)`-only code (the `tasklist` call in `src/apply.rs`) compiles under that target. Evidence: the command output and the `file` line in the report.
2. **Highest-version fxcfg.** Where v0 required exactly one `Graphics/Custom.*.fxcfg`, `apply`'s `ssaa` override now picks the file whose name parses as `Custom.<Major>.<Minor>.fxcfg` with the greatest `(Major, Minor)`; names that do not parse are ignored with a printed notice; zero parsable files is still an error. The chosen path is printed as `ssaa target: Graphics/Custom.4.4.fxcfg`. Test: temp profile with the fixture plus an added `Graphics/Custom.4.2.fxcfg` (copy of the 4.4 file) and `Graphics/Custom.fxcfg.bak` -> override lands in `Custom.4.4.fxcfg` only, the other two byte-identical, notice printed for the `.bak`. Close OBS-002 in `ISSUES.md` with the test name.
3. **Default Options dir.** `--options` becomes optional on `capture`, `apply`, and the `<bindings-dir>` positional on `check-binds` / `restore-preset` becomes optional: when absent, resolve `$LOCALAPPDATA/Frontier Developments/Elite Dangerous/Options` (and `/Bindings` for the binds commands); if `LOCALAPPDATA` is unset or the dir does not exist, exit 3 with a one-line message naming the path tried. The resolved path is printed. Test: run `capture` with `LOCALAPPDATA` pointed at a temp dir holding a copy of the fixture under `Frontier Developments/Elite Dangerous/Options` -> same result as criterion 1 of v0; with `LOCALAPPDATA` unset -> exit 3 and the message.
4. `ed-loadout --version` prints `ed-loadout 0.1.1`; `Cargo.toml` version bumped to `0.1.1`. Test: `assert_cmd` on `--version`.
5. `README.md` gains an **Install** section (download `ed-loadout.exe` from the latest GitHub Release, put it on PATH or run from the Options dir) and a **Two machines** walkthrough: on the desktop `ed-loadout capture --out desk --machine desk`, copy the `desk` folder across, on the laptop edit `profile.toml` to add `[machine.laptop]` with `ssaa` and `max_fps`, run `ed-loadout check-binds --devices ...`, then `ed-loadout apply desk --machine laptop`; one sentence each on what the backup is and how to undo. No invented numbers: the example `ssaa` for the laptop is written as a value to tune, not a recommendation.
6. `cargo test` green; `cargo clippy --all-targets -- -D warnings` clean; `cargo check --target x86_64-pc-windows-gnu` clean (this is what `build.yml` now runs).
