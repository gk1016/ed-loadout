# LOADOUT v0 — capture / diff / check-binds / apply / restore-preset

Rev 2 (2026-11-21) after Carbon critique on ed-loadout #1: binds-file resolution no longer trusts `StartPreset.4.start`, override-to-file mapping made explicit with paired tags, ED-UP ini deferred, greenfield waiver stated, citations fixed.

## Goal
A Rust CLI that captures an Elite Dangerous settings bundle from one machine, diffs two bundles, applies one to another machine with per-machine overrides and backups, and catches the two failures seen on devmachine02 on 2026-11-20 (bound device missing at launch; blind copy of render scale between GPUs).

## Non-goals
GUI. NVIDIA profile automation. Any game-memory read or d3d11 hook. Cloud sync. ED-UP `edvr.ini` / `edvr-flat.ini` (deferred to v0.1 until a real file is in the fixture corpus; v0 has no `--game-dir`). HID enumeration on Windows (v0 takes the device list as an argument or from `BindingLoadingErrors.log`).

## File set (the "bundle")
Relative to the Elite options dir (`%LOCALAPPDATA%\Frontier Developments\Elite Dangerous\Options`): `Graphics/Custom.*.fxcfg`, `Graphics/Settings.xml`, `Graphics/DisplaySettings.xml`, `Graphics/StartPreset.start`, `Graphics/GraphicsConfigurationOverride.xml`, `Bindings/*.binds`, `Bindings/StartPreset.*.start`. The fixture mirrors this under `fixtures/devmachine02/`.

## Binds-file resolution (shared by check-binds and the tests)
Elite overwrites `StartPreset.4.start` when a bound device is missing (`fixtures/devmachine02/Bindings/StartPreset.4.start.broken:1-4`), so it cannot be the source of truth. Order: (a) `--binds <file>` if given; (b) the file named on line 1 of `BindingLoadingErrors.log` (`...preset file: Custom.4.2.binds`) if that file exists; (c) the newest `Custom.4.*.binds` in the directory. The resolved path is printed.

## Acceptance criteria
1. `ed-loadout capture --options <dir> --out <profile> --machine <name>` copies the file set byte-for-byte into `<profile>/files/<relative path>` and writes `<profile>/profile.toml` with `source_machine`, `captured_at` (RFC 3339), and per-file `sha256`. Test: capture `fixtures/devmachine02`; every copied file's sha256 equals the source; a temp file written with CRLF line endings survives capture with identical bytes.
2. `ed-loadout diff <profile-a> <profile-b>` prints one line per changed XML element as `<relative path>: <ElementName> <old> -> <new>` for `.fxcfg`, `Settings.xml`, `DisplaySettings.xml` (flat child elements of the root), a unified line diff for `.start`, `.binds`, and `GraphicsConfigurationOverride.xml`; files present on one side only are listed as `only in a:` / `only in b:`. Exit 0 when identical, 1 when different. Test: fixture vs a copy with `SSAAMultiplier` `1.500000 -> 1.250000` prints exactly one element line and exits 1.
3. `ed-loadout check-binds <bindings-dir> (--devices <GUID,...> | --from-log) [--binds <file>]` resolves the binds file per the rule above, collects every `Device="..."` value except `Keyboard`, `Mouse`, `{NoDevice}`, and reports each GUID not in the device list with its binding count; `--from-log` takes missing GUIDs from `Failed to find GUID for device: <GUID>` lines. It also reads all four lines of `StartPreset.4.start` and warns for each line that is not `Custom`. Exit 1 when any GUID is missing or any preset line is not `Custom`. Tests: (a) fixture `Bindings/` with `--devices 231D0126,231D0127,231D2204` reports `045E0B22 (3 bindings)` and exits 1; (b) with `045E0B22` added, exits 0; (c) a temp copy with `StartPreset.4.start.broken` renamed over `StartPreset.4.start` and `--from-log` reports `045E0B22`, resolves `Custom.4.2.binds` from the log line, warns on lines 1-4, exits 1.
4. `ed-loadout restore-preset <bindings-dir> [--preset Custom]` rewrites `StartPreset.4.start` to four lines of the preset name, CRLF, after copying the old file to `StartPreset.4.start.bak-<timestamp>`. Test: the broken fixture copied to a temp dir -> result is exactly `Custom\r\n` x4; backup exists.
5. `ed-loadout apply <profile> --options <dir> --machine <name>` first copies every file it will overwrite to `<options>/_loadout-backup/<timestamp>/<relative path>`, then writes the profile files, then applies `[machine.<name>]` overrides from `profile.toml` by replacing element text in place and leaving every other byte unchanged. Mapping: `ssaa` (float, written as `%.6f`) -> `<SSAAMultiplier>` in the profile's `Graphics/Custom.*.fxcfg`; `screen_width` / `screen_height` -> `<ScreenWidth>` / `<ScreenHeight>` in `Graphics/DisplaySettings.xml`; `refresh_hz` -> `<DX11_RefreshRateNumerator>` and `<DX11_RefreshRateDenominator>` set to `1`; `max_fps` -> `<MaxFramesPerSecond>` and `<LimitFrameRate>` set to `true`. A target element that is absent is an error, never an insert. The running-game refusal (exit 2) is a function `game_running() -> bool` that shells `tasklist` behind `cfg(windows)` and returns `false` elsewhere with a printed notice; the refusal path is unit-tested by injecting `true`. Test: temp options dir pre-seeded with a copy of the fixture, apply the fixture profile with `[machine.laptop] ssaa = 1.25, max_fps = 120` -> `Custom.4.4.fxcfg` differs from the fixture only in the `SSAAMultiplier` line, `DisplaySettings.xml` only in `MaxFramesPerSecond` (`LimitFrameRate` already `true`), and `_loadout-backup/<ts>/` holds byte-identical pre-apply copies of both.
6. `cargo test` green on the WSL runner (the gate; `build.yml:35` runs only `cargo test`). `cargo clippy -- -D warnings` clean if clippy is installed on the runner; if not, say so in the report, not a failure. `README.md` documents the five commands with the devmachine02 example and states once, plainly: at Supersampling >= 1.0 ED-UP labels DLSS as DLAA and that is correct.
