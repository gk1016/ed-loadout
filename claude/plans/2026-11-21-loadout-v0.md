# LOADOUT v0 — capture / diff / check-binds / apply / restore-preset

## Goal
A Rust CLI that captures an Elite Dangerous settings bundle from one machine, diffs two bundles, applies one to another machine with per-machine overrides and backups, and catches the two failures seen on devmachine02 on 2026-11-20 (bound device missing at launch; blind copy of render scale between GPUs).

## Non-goals
GUI. NVIDIA profile automation. Any game-memory read or d3d11 hook. Cloud sync. ED-UP settings semantics beyond copying `edvr.ini` / `edvr-flat.ini` verbatim. HID enumeration on Windows (v0 takes the device list as an argument or from `BindingLoadingErrors.log`).

## Context
Kickoff: ED HUMINT Project doc `claude/loadout-kickoff-2026-11-20.md`. Seed crate: `Cargo.toml:1-6` (edition 2024, no deps), `src/main.rs:1-17` (greeting + one test). Fixture corpus from devmachine02 (verified by hand 2026-11-20): `fixtures/devmachine02/README.md` lists each file and what is real vs reduced. Lane issue: ed-loadout #1.

## File set (the "bundle")
Relative to the Elite options dir (`%LOCALAPPDATA%\Frontier Developments\Elite Dangerous\Options`): `Graphics/Custom.*.fxcfg`, `Graphics/Settings.xml`, `Graphics/DisplaySettings.xml`, `Graphics/StartPreset.start`, `Graphics/GraphicsConfigurationOverride.xml`, `Bindings/*.binds`, `Bindings/StartPreset.*.start`. Relative to the game dir (optional): `edvr.ini`, `edvr-flat.ini`. Fixture layout mirrors this under `fixtures/devmachine02/`.

## Acceptance criteria
1. `ed-loadout capture --options <dir> [--game-dir <dir>] --out <profile> --machine <name>` copies the file set byte-for-byte into `<profile>/files/<relative path>` and writes `<profile>/profile.toml` with `source_machine`, `captured_at` (RFC 3339), and per-file `sha256`. Test: capture `fixtures/devmachine02`; every copied file's sha256 equals the source; a temp file written with CRLF line endings survives capture with identical bytes.
2. `ed-loadout diff <profile-a> <profile-b>` prints one line per changed XML element as `<relative path>: <ElementName> <old> -> <new>` for `.fxcfg`, `Settings.xml`, `DisplaySettings.xml` (flat child elements of the root), a unified line diff for `.start`, `.ini`, `.binds`, and `GraphicsConfigurationOverride.xml`; files present on one side only are listed as `only in a:` / `only in b:`. Exit 0 when identical, 1 when different. Test: fixture vs a copy with `SSAAMultiplier` 1.500000 -> 1.250000 prints exactly one element line and exits 1.
3. `ed-loadout check-binds <bindings-dir> (--devices <GUID,...> | --from-log)` reads the active preset from `StartPreset.4.start` line 1, resolves `Custom.4.<n>.binds`, collects every `Device="..."` value except `Keyboard`, `Mouse`, `{NoDevice}`, and reports each GUID not in the device list with its binding count; `--from-log` takes missing GUIDs from `Failed to find GUID for device: <GUID>` lines in `BindingLoadingErrors.log`. Exit 1 when any GUID is missing. Test: fixture `Bindings/` with `--devices 231D0126,231D0127,231D2204` reports `045E0B22 (3 bindings)` and exits 1; with `045E0B22` added, exits 0.
4. `ed-loadout restore-preset <bindings-dir> [--preset Custom]` rewrites `StartPreset.4.start` to four lines of the preset name, CRLF, after copying the old file to `StartPreset.4.start.bak-<timestamp>`. Test: `fixtures/devmachine02/Bindings/StartPreset.4.start.broken` copied to a temp dir -> result is exactly `Custom\r\n` x4; backup exists.
5. `ed-loadout apply <profile> --options <dir> [--game-dir <dir>] --machine <name>` first copies every file it will overwrite to `<options>/_loadout-backup/<timestamp>/<relative path>`, then writes the profile files, then applies `[machine.<name>]` overrides from `profile.toml` (`ssaa`, `screen_width`, `screen_height`, `refresh_hz`, `max_fps`) by replacing the matching element text in place (`<SSAAMultiplier>`, `<ScreenWidth>`, `<ScreenHeight>`, `<DX11_RefreshRateNumerator>`, `<MaxFramesPerSecond>`), leaving every other byte of the file unchanged; a missing element is an error, not an insert. Refuses with exit 2 if `EliteDangerous64.exe` is running (Windows: `tasklist`; other OS: check skipped, printed). Test: apply the fixture profile with `[machine.laptop] ssaa = 1.25` into a temp options dir -> `Custom.4.4.fxcfg` differs from the fixture only in the `SSAAMultiplier` line; `_loadout-backup/` holds the pre-apply copies.
6. `cargo test` green on the WSL runner; `cargo clippy -- -D warnings` clean; `README.md` documents the five commands with the devmachine02 example and states once, plainly: at Supersampling >= 1.0 ED-UP labels DLSS as DLAA and that is correct.
