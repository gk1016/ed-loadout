# LOADOUT v0.2 — detect the machine, derive the deltas, apply with no flags

Rev 2 (2026-11-22) after Carbon critique on #1: derived-vs-`[machine]` merge made per-key, binds check source and skip rule defined, `t2` defined exactly, waiver stated, the two v0.1 tests that change are named, example value corrected, fixture dir untouched.

## Goal
`ed-loadout apply <profile>` on a fresh machine reads the panel, GPU and connected controllers itself, derives resolution / refresh / cap / Supersampling / terrain tier / override-XML tier from a table, prints every derived value with its reason, and applies, so nobody types a `[machine.*]` block by hand; any key the user does put in `[machine.<name>]` overrides the derived one.

## Non-goals
Measuring frame time or anything in-game (no hooks; the derived Supersampling is a documented starting point, never called "tuned"). VRR/G-Sync detection (VSync stays on, cap = refresh). GUI. ED-UP ini. Linux/macOS detection (facts come from a file there).

## Design
- **Facts** (`src/facts.rs`): `struct Facts { hostname, screen_w, screen_h, refresh_hz, gpu_name, gpu_vram_mb, devices: Vec<String /*VVVVPPPP*/> }`. Windows: `EnumDisplaySettingsExW(ENUM_CURRENT_SETTINGS)` primary display; DXGI `CreateDXGIFactory1` + `EnumAdapters1` first adapter without `DXGI_ADAPTER_FLAG_SOFTWARE` (`Description`, `DedicatedVideoMemory`); `GetRawInputDeviceList` + `GetRawInputDeviceInfoW(RIDI_DEVICENAME)` parsed for `VID_xxxx&PID_xxxx` (dedupe); hostname from `COMPUTERNAME`. Crate `windows-sys`, minimal features. Everywhere: `--facts <toml>` loads the same struct; `detect --dump <file>` writes it. `facts::load(cli) -> Option<Facts>`: `--facts` if given, else Windows detection, else `None` (printed once: `no device facts on this platform; pass --facts`). All `unsafe` stays in `src/facts.rs`.
- **Tiers** (`src/tiers.rs`, pure): GPU name -> T1 `RTX (5090|5080|4090)` not followed by `Laptop`; T2 `RTX (5090|5080) Laptop|RTX 5070 Ti|RTX 4080( SUPER)?|RTX 4070 Ti SUPER`; T3 otherwise. Derived: `screen_width/height/refresh_hz` from the panel; `max_fps = refresh_hz`; `ssaa = clamp(round05(sqrt(budget / (w*h))), 1.0, 1.5)`, budget 16.6 Mpx (T1), 10.0 Mpx (T2), fixed 1.0 (T3); `terrain_quality` 4 (T1) / 3 (T2, T3); `override_tier` t1 / t2 / none. Each prints `derived <key> = <value>  (<reason>)`, e.g. `derived ssaa = 1.1  (T2 budget 10.0 Mpx over 3840x2160; starting point: raise while GPU use stays under ~85%)`.
- **Merge rule** (`apply`): `facts` (if any) -> derived map; then `[machine.<name>]` (name = `--machine`, else `facts.hostname`) overrides key by key; then apply. No facts and no `[machine.<name>]` = v0.1 behaviour (`src/apply.rs:118`). Every effective key prints with its source: `derived` or `[machine.<name>]`.
- **Override XML tiers** (`tiers/t1.xml`, `tiers/t2.xml`, committed): t1 = `fixtures/devmachine02/Graphics/GraphicsConfigurationOverride.xml` byte-for-byte; t2 = t1 with the `DirectionalShadows_Ultra`, `SpotShadows_Ultra` and `Volumetrics` blocks (and their preceding comment blocks) removed. `override_tier` values: `t1`, `t2`, `captured` (write the profile's file, v0.1 behaviour, default when no facts), `none` (write nothing, leave the target's file alone, printed).
- **New `[machine]` keys**: `terrain_quality` (3|4 -> `<TerrainQuality>`), `override_tier` (above). Any fxcfg edit (`ssaa` or `terrain_quality`) goes through the same highest-version selection, prints `fxcfg target:`, and runs `refuse_newer_fxcfg`.
- **Binds check in `apply`**: scans the PROFILE's `files/Bindings/Custom.4.<n>.binds` (highest `<n>` by name, the file about to be written) for GUIDs and compares with `facts.devices`; runs only when facts exist. Without facts: one line `binds check skipped (no device facts)`; `--strict-binds` without facts is an error (exit 3) before any write.
