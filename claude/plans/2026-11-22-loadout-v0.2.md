# LOADOUT v0.2 — detect the machine, derive the deltas, apply with no flags

## Goal
`ed-loadout apply <profile>` on a fresh machine reads the panel, GPU and connected controllers itself, derives resolution / refresh / cap / Supersampling / terrain tier / override-XML tier from a table, prints every derived value with its reason, and applies, so nobody types a `[machine.*]` block by hand; an explicit `[machine.<name>]` or `--machine` still wins.

## Non-goals
Measuring frame time or anything in-game (no hooks; the derived Supersampling is a documented starting point, never called "tuned"). VRR/G-Sync detection (no reliable public API; VSync stays on, cap = refresh). GUI. ED-UP ini. Linux/macOS detection (facts come from a file there).

## Design
- **Facts** (`src/facts.rs`): `struct Facts { hostname, screen_w, screen_h, refresh_hz, gpu_name, gpu_vram_mb, devices: Vec<String /*VVVVPPPP*/> }`. Sources: on Windows, `EnumDisplaySettingsExW(ENUM_CURRENT_SETTINGS)` on the primary display, DXGI `EnumAdapters1` first hardware adapter (`DXGI_ADAPTER_DESC1`: Description, DedicatedVideoMemory), `GetRawInputDeviceList` + `GetRawInputDeviceInfoW(RIDI_DEVICENAME)` parsed for `VID_xxxx&PID_xxxx` (dedupe; keyboards/mice included, harmless). Crate `windows-sys` with only the features needed. Everywhere: `--facts <toml>` reads the same struct from a file; `detect --dump` writes it. Non-Windows without `--facts` is an error naming the flag.
- **Tiers** (`src/tiers.rs`, table in code, no I/O): GPU name regex -> tier. T1: desktop `RTX 5090|5080|4090`. T2: `RTX 5090 Laptop|5080 Laptop|5070 Ti|4080|4080 SUPER|4070 Ti SUPER`. T3: everything else (incl. unknown vendors). Derived: `screen_width/height/refresh_hz` from the panel; `max_fps = refresh_hz`; `ssaa = clamp(round05(sqrt(budget / (w*h))), 1.0, 1.5)` with budget 16.6 Mpx (T1), 10.0 Mpx (T2), 1.0 fixed (T3); `terrain_quality` 4 (T1), 3 (T2, T3); `override_tier` t1 / t2 / none. Every derived line prints as `derived <key> = <value>  (<reason>)`, e.g. `derived ssaa = 1.25  (T2 budget 10.0 Mpx over 3840x2160; starting point, raise while GPU use stays under ~85%)`.
- **Override XML tiers** (`tiers/t1.xml`, `tiers/t2.xml`, committed files): t1 = `fixtures/devmachine02/Graphics/GraphicsConfigurationOverride.xml` byte-for-byte; t2 = t1 with the `DirectionalShadows_Ultra` and `Volumetrics` blocks removed (stock shadows/volumetrics, keeps planets/galaxy/envmap/terrain). `none` = the profile's captured XML is NOT written and any existing target file is left alone (printed).
- **New override keys** in `[machine.<name>]`: `terrain_quality` (3|4 -> `<TerrainQuality>` in the chosen fxcfg) and `override_tier` (`t1|t2|none|captured`; default `captured` = today's behaviour).

## Acceptance criteria
1. `ed-loadout detect [--facts <file>] [--dump <file>]` prints the Facts and the derived deltas (reasons included) and exits 0; `--dump` writes the Facts as TOML. Tests (Linux, via `--facts`): fixture facts file `fixtures/devmachine02/facts.toml` (5120x1440, 120, "NVIDIA GeForce RTX 5090", 32607 MB, the four GUIDs) -> `ssaa = 1.5`, `terrain_quality = 4`, `override_tier = t1`, `max_fps = 120`; a laptop facts file (2560x1600, 240, "NVIDIA GeForce RTX 5090 Laptop GPU", 24 GB) -> T2, `ssaa = 1.5` (sqrt(10.0/4.1)=1.56 -> clamp), `terrain_quality = 3`, `override_tier = t2`; a 4K T2 case -> `ssaa = 1.1`; an unknown GPU -> T3, `ssaa = 1.0`, `override_tier = none`.
2. `apply <profile>` with no `--machine`: if `profile.toml` has no `[machine.<hostname>]`, run detection (Windows) or require `--facts`, print `detected machine: <hostname> (<gpu>, <w>x<h>@<hz>)`, derive, print each `derived` line, then apply exactly as if those values were in `[machine.<hostname>]`. `--machine <name>` or an existing `[machine.<hostname>]` table skips detection (printed). Test: fixture profile + laptop facts into a temp Options dir -> fxcfg `SSAAMultiplier 1.500000`, `TerrainQuality 3`, DisplaySettings 2560/1600/240/240, override XML equals `tiers/t2.xml`, backups present; with T3 facts the target's pre-existing override XML is byte-identical afterwards and a line says it was left alone.
3. `terrain_quality` and `override_tier` accepted in `[machine.<name>]` (`src/apply.rs:112-146`), unknown keys still rejected; `override_tier = captured` reproduces v0.1 behaviour byte-for-byte (existing apply tests unchanged and passing).
4. HID into binds: `check-binds` with neither `--devices` nor `--from-log` uses detected devices (Windows) or `--facts`; `apply` runs the same check before writing and prints `warning: bound device <GUID> (<n> bindings) is not connected` per missing GUID (exit stays 0; `--strict-binds` makes it exit 1 before writing). Tests: fixture binds + facts lacking `045E0B22` -> the warning; `--strict-binds` -> exit 1, nothing written.
5. Windows backend compiles under `cargo check --target x86_64-pc-windows-gnu` (`build.yml` already runs it) with `windows-sys` features limited to `Win32_Graphics_Gdi`, `Win32_Graphics_Dxgi`, `Win32_UI_Input`, `Win32_Foundation`, `Win32_System_SystemInformation` (or the minimal set that builds; list the final set in the report). No `unsafe` outside `src/facts.rs`.
6. README: a **Hands-off** section: `ed-loadout apply desk` on the new machine, what gets detected, the tier table, the sentence that the Supersampling is a starting point to raise while GPU use stays under ~85%, and how `[machine.<host>]` overrides any of it. Version `0.2.0`.
7. `cargo test` green; `cargo clippy --all-targets -- -D warnings` clean on both targets.
