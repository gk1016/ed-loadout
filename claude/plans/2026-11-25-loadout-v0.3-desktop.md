# LOADOUT v0.3 — a windowed app, not a console

Rev 2 (2026-11-25) after Carbon critique on #1: cap rule restated, the tests that change are named, test env guard for Windows, waiver stated, restore semantics defined, CLI binary shipped, installer evidence made checkable, names and model id corrected.

Graham, 2026-11-25 13:23 CT: "we are not doing command line stuff with our products." Double-clicking `LOADOUT_Portable.exe` on the laptop opened a console that closed at once. v0.3 makes LOADOUT a Qt desktop app in the FRAGO/S-4 grammar with a `LOADOUT_Setup.exe` installer. The CLI survives as the engine underneath and for scripting; it is no longer what a user sees.

## Goal
A commander installs `LOADOUT_Setup.exe`, opens LOADOUT, sees what the machine is and what will be applied, presses APPLY, and is done; every write is shown and backed up.

## Non-goals
No new detection or tier logic (v0.2 as is, plus the two v0.2.1 fixes folded in below). No self-update yet. No ED-UP ini. No cloud sync of profiles. No change to the CLI's flags.

tool rail 40px   : HOME / PROFILES / LOG / SETTINGS

  right : HOME pane - two ruled sections:
          DETECTED  (facts as label/value rows, controllers as GUID chips)
          WILL APPLY (one row per derived/overridden key: key, value, source, reason; file targets listed; bound devices from the selected profile that are not connected, in red)

## Acceptance criteria
1. **Repo shape**: crate moved to `rust/` as `loadout-core` (`crate-type = ["staticlib","rlib"]`, cxx), the CLI kept as `rust/src/bin/ed-loadout.rs` over the same library; the suite runs from `rust/` on the Windows runner. Because Windows would detect live hardware in the no-facts tests, `facts::load` honours `LOADOUT_NO_DETECT=1` (returns `None`, printed once), `build.ps1` sets it for `cargo test`, and the five `#[cfg(not(windows))]` tests drop the cfg and rely on that env so they run on Windows too. The v0.2.1 fixes land here: (a) GPU names containing `Laptop` other than `RTX 5090 Laptop` / `RTX 5080 Laptop` -> T3; (b) `max_fps`: if the panel refresh is <= 170 the cap is the refresh itself; otherwise the refresh divided by the smallest integer k that brings it to <= 170 (integer division) - 240->120, 360->120, 175->87, 165->165, 144->144, 120->120 - the reason names k; unit tests for both; version `0.3.0`. **Tests that change, by design**: `tests/cli.rs:498` and `:749` (version string), `:642` and `:706-722` (cap values), the fixture path at `:9-11` (`../fixtures`), the five cfg lines above. Nothing else in the test file changes; all 40 + 14 still run and pass.
2. **Bridge**: `rust/src/bridge.rs` (`#[cxx::bridge]`) exposes `detect() -> String` (JSON of Facts + derived rows), `list_profiles(dir) -> String`, `capture(options, out, machine) -> String`, `plan_apply(profile, options, machine) -> String` (the files, edits and not-connected bound devices that WOULD result, no writes), `apply(profile, options, machine) -> String` (result + backup path), `restore(options, backup) -> String`, `game_running() -> bool`. `apply` now always creates the backup folder and writes `manifest.toml` in it listing every file written and whether it pre-existed; `restore` puts pre-existing files back byte-for-byte and removes files that did not exist before (closes the `:124-139` observation in ISSUES.md). No panic can cross: every fn returns a JSON `{ok, error, ...}`; `unwrap`/`expect` lints as in FRAGO. Unit tests for manifest round-trip and restore-removes-added.
3. **Qt shell**: `CMakeLists.txt`, `cpp/main.cpp` (+ `cpp/core.h/.cpp` QObject wrapper exposing the bridge to QML with `Q_INVOKABLE`s and signals), `qml/Main.qml`, `qml/Theme.qml` (FRAGO's, tokens unchanged), `qml/Btn.qml`, `qml/Kicker.qml`, `qml/Rail.qml`, `qml/HomePage.qml`, `qml/ProfilesPage.qml`, `qml/LogPage.qml`, `qml/SettingsPage.qml`, `qml/ConfirmApply.qml`, `fonts/` (the three families, copied from FRAGO), `icons/loadout.ico` + an SVG mark (an original mark: a bracketed hexagon with a horizontal rule; no third-party art). Layout per the diagram; the design rules above are acceptance, checked on the survey shots. Built as a `WIN32` (GUI-subsystem) executable named `loadout.exe`.
4. **Scripts**: `build.ps1`, `package.ps1`, `ship.ps1 -NoRelease`, `shots.ps1 -Survey <tag>` and `loadout.iss` (`AppName=LOADOUT`, `{localappdata}\LOADOUT`, `OutputBaseFilename=LOADOUT_Setup`, Start-menu entry) adapted from FRAGO with names changed and the engine/Drive parts removed (LOADOUT has no engine, no Drive copy). `package.ps1` stages BOTH `loadout.exe` and `ed-loadout.exe` with the Qt runtime. `ship.ps1 -NoRelease` ends `=== VERIFY OK (no release) ===`; `shots.ps1 -Survey <tag>` writes `_shots\uipass\survey-<tag>\index.md` + jpgs for `home`, `profiles`, `log`, `settings`, `confirm` in deepfield and daylight at 1320 wide, log ends `=== SURVEY OK ===`.
5. **Behaviour on the box** (survey + a scripted run in `ship.ps1`): opening the exe with no profile folder shows HOME with DETECTED filled and WILL APPLY saying no profile yet; CAPTURE THIS MACHINE creates `%LOCALAPPDATA%\LOADOUT\profiles\<hostname>` and it appears in PROFILES; selecting a profile fills WILL APPLY with the merged rows (derived + `[machine.*]` sources); APPLY shows the confirm with the file list and backup path, writes, and the LOG page shows the lines; RESTORE LAST BACKUP puts the Options dir back (the scripted run hashes the Options dir with `Get-FileHash` before apply and after restore: same file set, same hashes). Game-running state disables APPLY and shows red in the status bar (`LOADOUT_FAKE_GAME_RUNNING=1`, read only in debug builds). The scripted run targets a scratch Options dir under `%TEMP%`, never the runner's real Elite Options.
6. **Installer**: `package.ps1` produces `..\transfer\LOADOUT_Setup.exe`. Checked on the runner: run it with `/VERYSILENT /SUPPRESSMSGBOXES`, then assert `%LOCALAPPDATA%\LOADOUT\loadout.exe` and `ed-loadout.exe` exist, the Start-menu `.lnk` exists under `%APPDATA%\Microsoft\Windows\Start Menu\Programs`, and `loadout.exe`'s PE optional-header Subsystem is 2 (WINDOWS_GUI), not 3 (console), read with a short PowerShell. Evidence: those four lines in the report plus a HOME shot of the installed exe. Uninstall afterwards with the generated `unins000.exe /VERYSILENT`.
7. **Docs**: `README.md` rewritten for the app (install, what the screen shows, where backups go, that `ed-loadout.exe` still exists for scripting); `ISSUES.md` updated; `CLAUDE.md` updated in this criterion (build host = Windows runner, `cargo test` from `rust/`, the "there is no UI" line removed). `.github/workflows/release.yml` is adjusted by Cowork after merge (not Code) to run `package.ps1` on the Windows runner and attach `LOADOUT_Setup.exe`.
