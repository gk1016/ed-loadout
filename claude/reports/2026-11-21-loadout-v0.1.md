## Deviations from the plan

- **Criterion 1 has no commit.** The cross-build already succeeded on the merged v0
  code; nothing to change. Evidence is the output above.
- **Which names get the "ignored" notice.** The plan says unparsable names are ignored
  with a notice, and its test expects one for `Custom.fxcfg.bak`, which v0's
  `Custom.*.fxcfg` filter would never have seen. The candidate set is therefore
  `Graphics/Custom.*` with `fxcfg` anywhere in the name; of those, only
  `Custom.<digits>.<digits>.fxcfg` parses. Comparison is numeric, so 4.10 beats 4.9.
- **Notice on stderr, `ssaa target:` on stdout**, matching v0 (notices on stderr,
  results on stdout).
- **Default-dir resolver lives in `src/main.rs`** (`default_dir`), not a new
  `src/paths.rs`: it is one function used only by the dispatch. The resolved path is
  printed (`options dir: ...` / `bindings dir: ...`) only when it was defaulted, so
  every v0 stdout assertion is unchanged. An empty `LOCALAPPDATA` counts as unset.
- **Newer fxcfg in the target is an error (Codex check 1, beyond the plan).** If the
  Options dir already holds a `Custom.<M>.<m>.fxcfg` newer than the profile's ssaa
  target, `apply` with `ssaa` exits 3 before any backup or write. Without this, the
  override lands in a file Elite ignores and apply reports success.
- **README** also updates the command synopses for the optional dirs, documents the
  ssaa target rule and the newer-fxcfg refusal, and adds the cross-build line under
  Build. The two-machine `check-binds` passes `--binds desk\files\Bindings\...` so it
  checks the desktop's binds before apply, and does not offer `--from-log` (Codex 4).
- The prompt's "SPA, migrations, scripts" and "local engine" do not apply: this is a
  CLI with no engine. Nothing was stood up, so nothing needed tearing down.
