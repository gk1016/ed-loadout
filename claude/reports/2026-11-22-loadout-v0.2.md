## Deviations from the plan

- **DXGI is not in windows-sys.** windows-sys 0.61 ships no COM interfaces, so
  `CreateDXGIFactory1` is declared in `src/facts.rs` with
  `#[link(name = "dxgi.dll", kind = "raw-dylib", modifiers = "+verbatim")]` (the same
  form `windows-link` uses for every windows-sys function), and `EnumAdapters1` /
  `GetDesc1` are called through hand-laid vtables (indices 12 and 10, from dxgi.h).
  DXGI needs no `CoInitialize`, so the stop-and-ask condition (COM initialisation that
  fails under `cargo check`) was not hit. It compiles, links and passes clippy for the
  gnu target. It has never run (OBS-007).
- **"Output identical to v0.1" with no facts.** Two lines the design requires are new
  in that path: `notice: no device facts on this platform; pass --facts <file>` and
  `binds check skipped (no device facts)`. Both go to stderr so v0.1 stdout is
  unchanged. Stdout gains `effective <key> = <value>  ([machine.<name>])` per override
  ("every effective key prints with its source") and `fxcfg target:`. Files written
  are byte-identical to v0.1, and every v0.1 test passes unchanged.
- **`fxcfg target:` and `ssaa target:`.** The design says any fxcfg edit prints
  `fxcfg target:`, and v0.1's `v01_c2_apply_ssaa_targets_highest_version_fxcfg`
  (which the plan does not list as changing) asserts `ssaa target:`. Both lines are
  printed when `ssaa` is set; `terrain_quality` alone prints only `fxcfg target:`.
  The newer-fxcfg refusal message now starts `fxcfg:` instead of `ssaa:`.
- **The machine note with facts.** v0.1's `note: no [machine.<name>] ...; applying
  the profile as captured` reads `...; using the derived values` when facts exist.
  With neither `--machine` nor facts: `note: no --machine and no device facts;
  applying the profile as captured`.
- **Binds check source.** The design's "profile's `files/Bindings/Custom.4.<n>.binds`
  (highest `<n>`)" is taken from the in-memory set of files about to be written.
  `<n>` is compared as a number. With no such file:
  `binds check skipped (profile has no Bindings/Custom.4.<n>.binds)`.
- **`check-binds --facts`** conflicts with `--devices` / `--from-log` (clap exit 2),
  so a facts file is never silently ignored.
- **`terrain_quality`** accepts only `3` or `4`, as the plan writes it. Facts TOML
  rejects unknown keys and needs all seven keys.
- **Windows detection failure** is `notice: device detection failed: <why>` and no
  facts, so `apply` falls back to v0.1 behaviour instead of exiting 3.
- **`detect --dump`** refuses an existing file. The plan does not say, and
  `CLAUDE.md` rule 8 says the tool never overwrites without a backup.
- **`max_fps` reason** reads `= refresh_hz; VRR is not detected, VSync is left as
  captured` instead of the plan's "VSync stays on" (Codex 1): `<VSync>` is never
  edited.
- **Tier patterns** are implemented as the plan's regexes read: unanchored and
  case-sensitive. See OBS-009.
- **t2.xml** removes exactly lines 73-116 and 129-139 of t1 (the three blocks, their
  comments and one trailing blank line each). It is well-formed (`xml.dom.minidom`),
  and t1's header comment is kept (OBS-011).
- **Scope words in the run prompt** ("SPA, migrations, scripts", "local engine") do
  not apply: this is a CLI with no engine. No engine was started, so none needed
  tearing down.
