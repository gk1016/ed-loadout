## Deviations from the plan

1. **A test outside the plan's list changed.** Criterion 2 says `apply` always creates
   the backup folder; `tests/cli.rs:383-384` (`c5_apply_crlf_target_keeps_crlf`)
   asserted there is none when nothing pre-existed, and criterion 1 says nothing else
   in the test file changes. The two cannot both hold. Criterion 2 is explicit and is
   what restore needs (an apply into an empty dir is the case with the most to
   remove), so the assertion now expects one backup folder holding only
   `manifest.toml`. `backup: <path> (0 files)` is printed in that case too.
2. **The plan's line list is off by one item.** `:749` is a cap expectation
   (`effective max_fps = 240`), not a version string; it is changed to 120 as the cap
   rule requires. The version test is renamed `v03_c1_version_is_0_3_0` (as v0.2 did).
3. **`.gitattributes`** (`fixtures/** -text`, `rust/tiers/** -text`). On this checkout
   (`core.autocrlf=true`) the fixture came out CRLF and 7 byte-comparing tests failed
   on main before any change. Not a behaviour change and the fixture's bytes in git
   are the same; without it the suite cannot pass on the Windows runner (OBS-019).
4. **`unwrap`/`expect` lints** are `#![warn(...)]` in `lib.rs` (off under `cfg(test)`),
   not `[lints.clippy]` in `Cargo.toml` as FRAGO has them: the Cargo table would also
   lint `tests/cli.rs`, which may not change, and fail `clippy --all-targets -D
   warnings`.
5. **`println!` became `say!` / `note!`** in the library modules (`rust/src/log.rs`):
   the CLI prints exactly what it did; under the bridge the same lines are collected
   for the LOG page. A GUI-subsystem exe has no stdout.
6. **Restore backs up first.** `CLAUDE.md` rule 8 (every overwrite is preceded by a
   backup) applies to restore too: it copies what it is about to replace into its own
   timestamp folder (`kind = "restore"`). RESTORE LAST BACKUP always means the last
   *apply* backup. Restore refuses while the game runs, like apply.
7. **No release path in `ship.ps1`.** The criterion names `ship.ps1 -NoRelease`; a
   release is `release.yml` on a tag (criterion 7, Cowork). Without `-NoRelease` the
   script aborts and says so. FRAGO's commit/push/`gh release create`/publish/Drive
   half was not ported. `package.ps1` (not `ship.ps1`) compiles the installer, as
   criterion 6 says, and writes no self-updater manifest (no self-update in v0.3).
8. **`deploy.ps1`** (windeployqt) exists as in FRAGO; the plan's list does not name it.
   The MSVC runtime is staged into `dist\LOADOUT` by `package.ps1` (from
   `..\transfer\crt`, else the toolset's Redist folder) instead of being an Inno
   source outside the repo, so the installer builds on a runner without that folder.
9. **Debug-only fake switch.** `LOADOUT_FAKE_GAME_RUNNING` is read in debug builds
   only, so the packaged exe cannot show the state. CMake also builds
   `build\loadout-dbgcore.exe` (same shell, debug core, never packaged) and
   `ship.ps1` / `shots.ps1` use it for that one check. `build.ps1` runs `cargo test`
   in the debug profile (FRAGO: `--release`) so the switch's unit test means something.
10. **The tool rail is a 40 px wide column** (FRAGO's Rail furniture, LOADOUT's own
    width), read from "tool rail 40px" in the layout; Theme's rail tokens (64 px at
    this density) are untouched. If a 40 px high strip was meant, it is one file.
11. **`Btn` and `Kicker` use Barlow Condensed**, not FRAGO's Michroma: the plan ships
    the three families only. Extra QML beyond the list: `PaneHead`, `Field`, `Mark`.
12. **Survey has 15 captures, not 10**: the plan's five screens in both themes, plus
    `home-empty` and `home-game-running` in both, plus `installed-home`. The survey
    tag rule in `shots.ps1` allows a dot, because this wave's slug has one (OBS-020).
13. **Theme and paths are saved by `Core` (QSettings), not QML `Settings`**: a harness
    run (`--options`, `--profiles`, `--theme`, `--select`) must save nothing.
14. **Small additions:** PROFILES page shows the selected profile's files and SHA-256;
    CAPTURE THIS MACHINE on an existing `<hostname>` profile makes
    `<hostname>-<timestamp>` instead of failing; `tasklist` runs with
    `CREATE_NO_WINDOW`; DEFAULT group in the Start menu is `ED HUMINT` like the
    siblings; the desktop shortcut task is unchecked by default.
